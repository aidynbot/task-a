# Извлечение данных из финансовых документов

Небольшой сервис для разбора текстов счетов, коммерческих предложений и актов. Он возвращает JSON по фиксированной схеме и проверяет результат программно. Основной принцип — не выводить отсутствующий реквизит из догадки: если значения нет, оно должно быть `null`; обнаруженные проверки и сбои отражаются в `warnings`.

## Возможности

- HTTP API на FastAPI: `POST /parse`, страница документации `/docs` и проверка состояния `/health`.
- Провайдер Gemini со структурированным JSON-ответом и локальный эвристический `MockProvider` для запуска без API-ключа.
- Pydantic-модели для валидации ответа, повторные попытки после ошибки формата и безопасный ответ `unknown`, если извлечение не удалось.
- Guardrails: нормализация OCR-ошибок в БИН/ИИН, проверка наличия номера, БИН/ИИН и признаков даты в исходном тексте, арифметическая сверка позиций и проверка явных маркеров освобождения от НДС.
- Набор из 10 входных документов с JSON-эталонами в `dataset/inputs` и `dataset/expected`: три документа из задания и семь дополнительных, включая OCR-шум, неполные данные, текст на казахском и русском, суммы прописью и противоречивые реквизиты.
- `eval.py` сравнивает извлечённые значения с эталонами и отдельно считает точность по полям, ложные заполнения (галлюцинации) и пропуски.

## Запуск на Windows

Требуются Python 3.11 или новее и GNU Make. Из корня проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
make install
```

`make install` устанавливает зависимости из `requirements.txt` в `.venv`. Makefile выбирает этот интерпретатор на Windows; для другого Python можно передать, например, `make test PYTHON=python`.

Создайте локальный `.env` из шаблона и при необходимости укажите Gemini API key:

```powershell
Copy-Item .env.example .env
```

Если ключ не задан, приложение автоматически использует `MockProvider`. Для принудительного локального режима установите `USE_MOCK=true` в `.env` или передайте `"use_mock": true` в запросе.

Запустить сервис:

```powershell
make run
```

По умолчанию API доступно на `http://127.0.0.1:8000`; интерактивная документация — `http://127.0.0.1:8000/docs`.

Пример запроса:

```powershell
Invoke-RestMethod -Method Post `
  -Uri http://127.0.0.1:8000/parse `
  -ContentType 'application/json' `
  -Body '{"text":"Счет № 12 от 12.11.2026. Итого: 25 000 тенге.","use_mock":true}'
```

## Контракт ответа

Ответ включает `doc_type`, `supplier_name`, `supplier_bin`, `doc_number`, `doc_date`, `currency`, `total_amount`, `vat_amount`, `line_items`, `field_confidence` и `warnings`. Типы, обязательные поля и допустимые значения заданы моделями в `app/schemas.py`; дата должна быть ISO `YYYY-MM-DD`, а БИН/ИИН — ровно 12 цифр. Неуказанные значения представлены как `null`, позиции — как список объектов с названием и количеством/ценой, которые также могут быть `null`.

Перед передачей клиенту результат проходит выходную Pydantic-валидацию. Ошибка провайдера или исчерпание повторов возвращает объект с `doc_type: "unknown"`, пустыми реквизитами и пояснением в `warnings`, а не необработанный JSON модели.

### Противоречия и ограничения

Номер документа, БИН/ИИН и наличие признаков даты сверяются с исходным текстом. Арифметическая проверка предупреждает, если сумма позиций не совпадает с итогом (с учётом отдельно указанного НДС). Явное «без НДС» удаляет извлечённую сумму НДС, кроме случая, когда рядом явно указана сумма налога. В текущей версии нет универсального выбора между несколькими датами или несколькими строками «Итого»: эти конфликты не разрешаются отдельным правилом во всех форматах документов, поэтому этот сценарий остаётся ограничением и требует расширения guardrails и eval.

`MockProvider` — демонстрационная эвристика, а не полноценная языковая модель: качество извлечения сложных таблиц и сумм прописью ограничено. Gemini может точнее извлекать такие поля, но его ответ всё равно проходит те же проверки. Значения `field_confidence` — оценка провайдера, скорректированная отдельными guardrails; это не калиброванная вероятность.

## Тесты и оценка

```powershell
make test
make lint
make eval-mock
```

`make eval-mock` запускает весь набор без сетевых запросов. Для оценки в автоматическом режиме настройте ключ Gemini в `.env` и запустите `make eval`; команда использует паузу между документами и сохраняет JSON-отчёт в `eval_report.json`. Без ключа настройки автоматически переключают пайплайн на mock-провайдер, поэтому для локальной проверки без ожидания используйте `make eval-mock`.

Можно вызвать evaluator напрямую с другими каталогами:

```powershell
.\.venv\Scripts\python.exe -X utf8 eval.py --mock --inputs dataset/inputs --expected dataset/expected
```

## Структура проекта

```text
app/                 API, схемы, pipeline, guardrails и провайдеры
dataset/inputs/      входные тексты документов
dataset/expected/    эталонный JSON для каждого входа
tests/               тесты API, схем и guardrails
eval.py              сравнение результата с эталонами
Makefile             команды установки, запуска, тестов и оценки
```
